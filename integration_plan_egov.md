# План интеграции сайтов validation.kg и egov.kg

Этот документ содержит детальный технический анализ, варианты интеграции, требования к API на стороне **validation.kg** (Django REST Framework) и проект технического задания (ТЗ) для команды государственного портала **egov.kg** (включая стандарты взаимодействия в КР, такие как СМЭВ «Түндүк»).

---

## 1. Технические варианты интеграции

Для динамического отображения данных с `validation.kg` на `egov.kg` существует несколько подходов. Рассмотрим их преимущества и недостатки:

| Вариант | Описание | Плюсы | Минусы |
| :--- | :--- | :--- | :--- |
| **1. REST API (JSON)**<br>*(Рекомендуемый)* | Бэкенд `validation.kg` отдает данные в формате JSON через защищенные эндпоинты, а `egov.kg` запрашивает их по расписанию (cron) или при загрузке страниц. | • Высокая скорость работы.<br>• Полный контроль над структурой данных.<br>• Легко кэшировать.<br>• Стандарт индустрии. | • Требует разработки фронтенда отображения на стороне `egov.kg`. |
| **2. RSS / Atom лента** | Стандартный формат синдикации контента. validation.kg генерирует XML-ленту новостей, а egov.kg импортирует её. | • Крайне простая реализация.<br>• Поддерживается почти всеми CMS из коробки. | • Подходит **только для новостей**.<br>• Не подходит для базы сертифицированных специалистов или контактов. |
| **3. Webhooks (Вебхуки)** | При добавлении новости на `validation.kg` наш сервер отправляет POST-запрос на `egov.kg`, сообщая об изменении. | • Моментальное обновление (Real-time).<br>• Экономия ресурсов серверов. | • Сложно настроить безопасность гос. портала (фаерволы egov.kg могут блокировать входящие запросы). |
| **4. Iframe / Widget Embed** | `egov.kg` встраивает готовую визуальную страницу с `validation.kg` через тег `<iframe>`. | • Не требует программирования со стороны `egov.kg` (просто вставить HTML-код). | • Плохо влияет на SEO.<br>• Проблемы с адаптивностью дизайна.<br>• Часто блокируется политиками безопасности гос. сайтов (CSP). |
| **5. Веб-парсинг (Scraping)** | Скрипт на стороне `egov.kg` читает HTML-код страниц `validation.kg` и извлекает информацию. | • Не требует изменений на стороне `validation.kg`. | • Хрупкое решение. Любое изменение верстки на `validation.kg` мгновенно ломает интеграцию. |

## 2. Специфика интеграции с госсистемами КР (СМЭВ «Түндүк»)

Государственный портал электронного правительства КР (`egov.kg`) и государственные информационные системы часто подчиняются жестким требованиям безопасности ГП «Инфоком» и ГКИТ КР.

* **СМЭВ «Түндүк» (Электронное взаимодействие)**: В Кыргызстане действует единая система межведомственного электронного взаимодействия (СМЭВ «Түндүк»), построенная на базе эстонской платформы *X-Road*. Если интеграция касается обмена критическими персональными данными граждан (например, реестра сертифицированных специалистов для официальных госорганов), `egov.kg` может потребовать подключение через шлюз безопасности «Түндүк».
* **REST API через HTTPS**: Для публичной информации (новости, контакты, общая статистика) сложная процедура регистрации в «Түндүк» избыточна. Достаточно предоставить документированный публичный **REST API** с авторизацией по токену (`Bearer Token` / `API Key`) по протоколу HTTPS.

## 3. Что нужно реализовать на стороне validation.kg

Поскольку **validation.kg** работает на связке **Django (Python)** + **PostgreSQL** на бэкенде, мы можем быстро реализовать необходимые эндпоинты с помощью **Django REST Framework (DRF)**.

Необходимо создать три API-эндпоинта (Endpoints) со следующим форматом данных:

### 1. Новости (News Endpoint)
* **URL**: `/api/v1/external/news/`
* **Метод**: `GET`
* **Параметры**:
  * `limit` (int) — количество новостей на страницу (по умолчанию 10).
  * `page` (int) — номер страницы.
  * `lang` (str) — язык (`ru`, `ky`).
* **Пример ответа (JSON)**:
```json
{
  "count": 143,
  "next": "https://validation.kg/api/v1/external/news/?page=2",
  "previous": null,
  "results": [
    {
      "id": 143,
      "title": "Опытный сантехник строительной отрасли Бектур Жапар уулу успешно прошёл валидацию",
      "slug": "opytnyj-santehnik-stroitelnoj-otrasli",
      "created_at": "2026-07-09T06:25:44Z",
      "image_url": "https://validation.kg/media/news/ocherednoj-etap-validatsii-po-profe/ocherednoj-etap-validatsii-po-profe_n7E7nhO.webp",
      "description_short": "9 июля 2026 года в Независимом центре сертификации...",
      "description_full": "<p>Полный HTML-текст новости...</p>"
    }
  ]
}
```

### 2. Информация о центре (Organization Info Endpoint)
* **URL**: `/api/v1/external/about/`
* **Метод**: `GET`
* **Пример ответа (JSON)**:
```json
{
  "name_ru": "Центр независимой сертификации и валидации при МП КР",
  "name_ky": "Кыргыз Республикасынын Агартуу министрлигине караштуу Көз карандысыз сертификациялоо жана валидациялоо борбору",
  "about_ru": "Деятельность Центра направлена на подтверждение и признание компетенций...",
  "about_ky": "Борбордун ишмердүүлүгү тиешелүү квалификацияны ыйгаруу...",
  "contacts": {
    "address_ru": "ул. Байтик Баатыра, 122",
    "address_ky": "Байтик Баатыр көчөсү, 122",
    "phone": "+996 312 59 14 01",
    "email": "icvccentre@gmail.com",
    "working_hours": "09:00 - 18:00 (Пн - Пт)"
  }
}
```

### 3. Реестр сертифицированных специалистов (Optional Verification API)
Если на `egov.kg` требуется форма поиска/проверки специалистов:
* **URL**: `/api/v1/external/certified-users/verify/`
* **Метод**: `GET`
* **Параметры**:
  * `query` (string) — ФИО, ИНН или номер сертификата.
* **Пример ответа (JSON)**:
```json
{
  "found": true,
  "data": {
    "registration_number": "ЦС № 000680",
    "full_name": "Жапар уулу Бектур",
    "profession": "Слесарь-сантехник",
    "issued_date": "2026-07-09",
    "status": "Действителен"
  }
}
```

## 4. Проект технического задания (ТЗ) для команды egov.kg

Ниже представлен готовый текст, который вы можете передать техническим специалистам портала `egov.kg`:

```markdown
# ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ К ИНТЕГРАЦИИ ДАННЫХ

## 1. Введение
Настоящие требования описывают порядок интеграции данных между официальным сайтом Независимого центра сертификации и валидации (https://validation.kg) и государственным порталом электронного правительства КР (https://egov.kg).

Цель интеграции — автоматическое и динамическое отображение информации о Центре (раздел «О нас», контакты, новостная лента) на портале egov.kg без необходимости ручного дублирования контента.

## 2. Метод интеграции
Интеграция осуществляется посредством вызова RESTful API на стороне validation.kg. 
Формат передачи данных: JSON.
Протокол передачи: HTTPS.
Авторизация запросов: API-Key / Bearer Token в заголовке запроса (будет предоставлен технической службой Центра).

## 3. Доступные эндпоинты (Endpoints)
Бэкенд validation.kg предоставляет следующие эндпоинты:

1. Лента новостей: `GET https://validation.kg/api/v1/external/news/`
   * Отдает пагинационный список новостей (заголовок, дата, превью-картинка, краткое описание, полный текст) с поддержкой русского и кыргызского языков.
2. Информация о центре и контакты: `GET https://validation.kg/api/v1/external/about/`
   * Отдает текстовое описание организации, адреса, телефоны, email.

## 4. Требования к реализации на стороне egov.kg
1. Настроить периодический опрос (например, раз в 1-2 часа через планировщик задач/cron) эндпоинта новостей с кэшированием результатов на стороне egov.kg для оптимизации скорости загрузки страниц.
2. Настроить автоматическое наполнение страниц:
   - `egov.kg/ru/subordinate/certification-validation/news-gallery` — наполняется данными из эндпоинта новостей.
   - `egov.kg/ru/subordinate/certification-validation/4886` — наполняется данными из эндпоинта информации о Центре.
3. Добавить ссылки, телефон, адрес и логотип Центра на страницу `egov.kg/ru/agencies` на основе данных из эндпоинта о контактах.
```

## 5. Пошаговый план действий

### Шаг 1. Переговоры и согласование (Срок: 1-2 недели)
1. Вы отправляете подготовленное ТЗ (раздел 4) куратору со стороны `egov.kg` или в ГП «Инфоком» (разработчикам госпортала).
2. Согласуете техническую возможность: могут ли они делать HTTP-запросы наружу к вашему API, или у них закрытый контур и требуется интеграция строго через шлюзы «Түндүк».
3. *Результат*: Письменное подтверждение от egov.kg с выбранным форматом интеграции.

### Шаг 2. Разработка на стороне validation.kg (Срок: 3-5 дней)
1. Разработчик бэкенда `validation.kg` создает файлы сериализаторов и вью-классы (Django REST Framework) для отдачи JSON на `/api/v1/external/...`.
2. Включается генерация Swagger/OpenAPI документации для удобства разработчиков госпортала.
3. Настраивается генерация API токена для egov.kg (чтобы защитить бэкенд от лишних нагрузок).
4. *Результат*: Ссылка на работающий API и токен доступа.

### Шаг 3. Тестирование и подключение на стороне egov.kg (Срок: 1-2 недели)
1. Разработчики `egov.kg` подключают ваши эндпоинты в тестовой среде.
2. Проверяют корректность отображения кириллицы (в т.ч. кыргызских символов Ө, Ү, Ң) и верстку картинок.
3. Настраивают кэширование, чтобы госпортал не перегружал ваш сервер запросами при каждом визите пользователя.
4. *Результат*: Наполнение страниц новостей и контактов на тестовом сервере egov.kg работает автоматически.

### Шаг 4. Запуск в продакшн (Срок: 1 день)
1. Перевод интеграции на боевые адреса.
2. Контрольная проверка отображения контента.
