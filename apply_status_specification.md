# Техническая спецификация: Электронная приемная и Статус заявки

Этот документ описывает структуру данных, этапы подачи заявок и статусы прохождения валидации/сертификации кандидатов на сайте **validation.kg**, которые могут быть интегрированы на портале **egov.kg**.

---

## 1. Электронная приемная (Подача заявки)

Форма подачи заявки (`https://validation.kg/apply`) разделена на **4 последовательных шага**:

### Шаг 1. Личные данные кандидата
* **ФИО кандидата** (`full_name`) — текстовое поле, обязательно.
* **Год рождения** (`birth_year`) — целое число, необязательно.
* **ИНН / ПИН** (`inn`) — ровно 14 цифр (персональный идентификационный номер гражданина КР), обязательно.
* **Телефон** (`phone`) — текстовое поле, обязательно.
* **E-mail** (`email`) — электронная почта, обязательно.
* **Адрес проживания** (`address`) — текстовое поле, необязательно.

### Шаг 2. Выбор профессии и квалификации
* **Профессия** (`profession`) — выбор из справочника (`Profession`) или свободный текст.
* **Квалификационный уровень** (`qualification_level`) — желаемый разряд/класс квалификации.
* **Тип процедуры** (`application_type`) — выбор одного из двух вариантов (обязательно):
  1. `certification` (Сертификация) — для граждан с формальным профессиональным образованием.
  2. `validation` (Валидация) — для граждан с практическим опытом (без диплома), желающих подтвердить навыки.
* **Опыт работы** (`experience_years` / `experience_desc`) — стаж работы по специальности в годах и краткое описание опыта.

### Шаг 3. Документы (Портфолио доказательств)
Кандидат загружает сканированные копии документов (файлы в форматах PDF, JPG, PNG):
* **Копия паспорта** (обязательно).
* **Документы об образовании** (дипломы, сертификаты курсов, если есть).
* **Подтверждение опыта работы** (копия трудовой книжки, контрактов или рекомендательных писем).

### Шаг 4. Подтверждение и согласие
* Экран финальной проверки заполненных данных.
* **Согласие на обработку данных** (`data_consent`) — флажок (чекбокс) обязательного согласия с правилами оценки.

## 2. Статусы заявки (Жизненный цикл процесса)

После успешной отправки заявке присваивается уникальный UUID-идентификатор (регистрационный номер) и стартовый статус. В процессе прохождения оценки администратор в Django-панели меняет статус заявки:

| Идентификатор статуса в базе | Отображение для кандидата | Описание |
| :--- | :--- | :--- |
| `draft` | **Черновик** | Заявка заполнена, но еще не отправлена в обработку. |
| `submitted` | **Подана** | Кандидат отправил заявку. Она ожидает первичной проверки специалистом. |
| `under_review` | **На рассмотрении** | Менеджер проверяет полноту документов в портфолио. |
| `assessment_scheduled` | **Оценка назначена** | Документы одобрены. Кандидату назначена дата и место проведения практического экзамена. |
| `assessment_in_progress` | **Оценка проводится** | Кандидат сдает теоретический или практический тест перед комиссией. |
| `approved` | **Одобрена** | Комиссия вынесла положительное решение о подтверждении квалификации. |
| `rejected` | **Отклонена** | Заявка отклонена (например, из-за неполного пакета документов или несдачи экзамена). |
| `cancelled` | **Отменена** | Заявка отменена по инициативе кандидата. |
| `completed` | **Завершена** | Процедура полностью завершена, кандидату выдан государственный сертификат. |

---

## 3. Логика проверки статуса (`https://validation.kg/apply/status`)

Кандидат переходит на страницу статуса, где:
1. Вводит свой **ИНН (14 цифр)** или **Регистрационный номер заявки** (UUID).
2. Система делает запрос к базе данных и выводит:
   * Текущий статус (например, «Оценка назначена» с указанием даты, времени и места экзамена).
   * Комментарии администратора (например, «Пожалуйста, донесите оригинал трудовой книжки»).
